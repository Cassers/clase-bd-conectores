¿Qué es una base de datos?

      
Una base de datos guarda información de forma organizada para que muchos programas la consulten sin perderla ni duplicarla. Hay dos grandes familias.

      

        
RelacionalNo relacional (NoSQL)

        
EjemplosPostgreSQL, MySQL, SQL Server, OracleMongoDB, Firebase, Redis, DynamoDB

        
FormaTablas con filas y columnas fijasDocumentos JSON, clave-valor, grafos

        
EsquemaSe define antes de guardarFlexible: cada registro trae sus campos

        
RelacionesJOIN usando llavesDatos anidados o duplicados

        
GarantíasACID: todo o nadaVaría; prioriza escala y velocidad

        
Úsala paraUsuarios, pedidos, notas, pagosLogs, catálogos cambiantes, caché, chats

      

      
Llave primaria: identifica cada fila (id). Llave foránea: una columna que apunta a otra tabla (escuadron_id → escuadrones.id).

      
-- Relacional: unir tablas por sus llaves
SELECT t.nombre, e.nombre AS escuadron
FROM tripulantes t
JOIN escuadrones e ON e.id = t.escuadron_id;

-- "No relacional": cada documento trae los campos que quiera
SELECT documento->>'nave' AS nave, documento->'alertas' AS alertas
FROM reportes_nave
WHERE documento ? 'alertas';

SQL: CRUD e INSERT

      
SQL es el idioma universal de las bases relacionales: lo que aprendas aquí sirve en Postgres, MySQL y SQL Server. Todo sistema hace cuatro cosas con sus datos, y se resumen en CRUD.

      

        
LetraSQLEjemplo

        
CreateINSERTINSERT INTO misiones (nombre, destino, dificultad) VALUES ('X', 'Marte', 2);

        
ReadSELECTSELECT nombre, puntos FROM tripulantes WHERE rango = 'Piloto';

        
UpdateUPDATEUPDATE tripulantes SET puntos = 100 WHERE id = 3;

        
DeleteDELETEDELETE FROM tripulantes WHERE id = 3;

      

      
UPDATE y DELETE sin WHERE afectan toda la tabla. Es el error más famoso de las pasantías. Antes de ejecutarlos, prueba el mismo WHERE con un SELECT.

      
Los 7 INSERT que más vas a usar

      
-- 1) Una fila, nombrando columnas (siempre nombrarlas)
INSERT INTO escuadrones (nombre, color) VALUES ('Pegaso', 'blanco');

-- 2) Varias filas de una vez
INSERT INTO misiones (nombre, destino, dificultad) VALUES
  ('Ruta de Hielo', 'Europa', 2),
  ('Faro Rojo',     'Marte',  3);

-- 3) Dejar que la base ponga los DEFAULT (rango, puntos, fecha...)
INSERT INTO tripulantes (nombre, email, escuadron_id)
VALUES ('Alejo', 'alejo@discamus.net', 1);

-- 4) RETURNING: devuelve el id que generó la base (clave desde código)
INSERT INTO tripulantes (nombre, email, escuadron_id)
VALUES ('Lucía', 'lucia@discamus.net', 2)
RETURNING id, rango, puntos;

-- 5) INSERT ... SELECT: insertar el resultado de una consulta
INSERT INTO asignaciones (tripulante_id, mision_id, rol)
SELECT t.id, m.id, 'Piloto'
FROM tripulantes t, misiones m
WHERE t.rango = 'Piloto' AND m.nombre = 'Faro Rojo';

-- 6) No fallar si ya existe
INSERT INTO escuadrones (nombre, color) VALUES ('Orión', 'azul')
ON CONFLICT (nombre) DO NOTHING;

-- 7) Upsert: si existe, actualiza
INSERT INTO escuadrones (nombre, color) VALUES ('Orión', 'azul eléctrico')
ON CONFLICT (nombre) DO UPDATE SET color = EXCLUDED.color;

Procedimientos y funciones

      
    
        
  • PROCEDURE: ejecuta acciones (insertar, actualizar, registrar). Se llama con CALL.
    • 
        
  • FUNCTION: devuelve un valor o una tabla. Se usa dentro de un SELECT.
    • 
        
  • La lógica vive dentro de la base: es igual para cualquier lenguaje que se conecte, y se ejecuta todo o nada.
    • 
      

      
CREATE PROCEDURE transferir_puntos(p_origen int, p_destino int, p_cantidad int)
LANGUAGE plpgsql AS $$
BEGIN
  UPDATE tripulantes SET puntos = puntos + p_cantidad WHERE id = p_destino;

  -- Si el origen no tiene suficientes, el error deshace TODO,
  -- incluido el UPDATE de arriba. Nadie gana puntos de la nada.
  IF (SELECT puntos FROM tripulantes WHERE id = p_origen) < p_cantidad THEN
    RAISE EXCEPTION 'Puntos insuficientes';
  END IF;

  UPDATE tripulantes SET puntos = puntos - p_cantidad WHERE id = p_origen;
END;
$$;

CALL transferir_puntos(1, 8, 100);        -- procedimiento: CALL
SELECT * FROM ranking_escuadron(1);       -- función: dentro de un SELECT

El conector seguro

      
Un conector (o driver) es la librería que permite que un lenguaje hable con la base. En C# con PostgreSQL se llama Npgsql; con SQL Server es Microsoft.Data.SqlClient, en Java es JDBC y en Python, psycopg. Hay tres reglas para que el puente sea seguro:

      

        
ReglaMalBien

        
1. La clave no va en el códigoPassword=MiClave123 en Program.csEn .env o variables de entorno; .env va en .gitignore

        
2. Cifrado, no texto planoSslMode=DisableSslMode=Require (o VerifyFull): TLS cifra todo lo que viaja

        
3. Parámetros, nunca texto pegado$"... WHERE usuario = '{usuario}'"WHERE usuario = @usuario + Parameters.AddWithValue

      

      
var builder = new NpgsqlConnectionStringBuilder
{
    Host = Environment.GetEnvironmentVariable("DB_HOST"),
    Username = Environment.GetEnvironmentVariable("DB_USER"),
    Password = Environment.GetEnvironmentVariable("DB_PASSWORD"),   // sale de .env
    Database = "postgres",
    SslMode = SslMode.Require,                                     // conexión cifrada
};
await using var fuente = NpgsqlDataSource.Create(builder.ConnectionString);

await using var cmd = fuente.CreateCommand(
    "SELECT usuario, nivel FROM codigos_acceso WHERE usuario = @usuario AND clave = @clave");
cmd.Parameters.AddWithValue("usuario", usuario);   // el dato viaja aparte del SQL
cmd.Parameters.AddWithValue("clave", clave);

Tramo 5 de 7 · 15 min

      
CRUD dentro del código

      
El mismo CRUD del tramo 2, ahora desde C#. Cada letra es un método que envía SQL con parámetros. Este patrón (una clase "repositorio" por tabla) es el que vas a ver en casi cualquier empresa.

      
class TripulantesRepositorio(NpgsqlDataSource fuente)
{
    public async Task<int> Crear(string nombre, string email, int escuadronId)
    {
        await using var cmd = fuente.CreateCommand(
            "INSERT INTO tripulantes (nombre, email, escuadron_id) " +
            "VALUES (@nombre, @email, @escuadron) RETURNING id");
        cmd.Parameters.AddWithValue("nombre", nombre);
        cmd.Parameters.AddWithValue("email", email);
        cmd.Parameters.AddWithValue("escuadron", escuadronId);
        return (int)(await cmd.ExecuteScalarAsync())!;     // C: devuelve el id
    }

    public async Task<int> Eliminar(int id)
    {
        await using var cmd = fuente.CreateCommand("DELETE FROM tripulantes WHERE id = @id");
        cmd.Parameters.AddWithValue("id", id);
        return await cmd.ExecuteNonQueryAsync();            // D: filas borradas
    }
    // Listar() y BuscarPorId() usan ExecuteReaderAsync; SumarPuntos() es un UPDATE
}

      

        
Método de NpgsqlPara quéDevuelve

        
ExecuteReaderAsyncSELECT con varias filasUn lector que recorres fila por fila

        
ExecuteScalarAsyncUn solo valor (un id, un COUNT)Ese valor

        
ExecuteNonQueryAsyncINSERT, UPDATE, DELETE, CALLCuántas filas cambiaron

LINQ

      
LINQ es de C#, no de la base de datos. Sirve para consultar cualquier colección: listas, arreglos y, con Entity Framework Core, tablas. EF traduce tu LINQ a SQL y lo envía con parámetros, así que también te protege de la inyección.

      
// LINQ sobre una lista normal, sin base de datos
int[] puntos = [980, 120, 650, 90, 720];
var altos = puntos.Where(p => p > 500).OrderBy(p => p);     // 650, 720, 980

// LINQ sobre la base con Entity Framework
var pilotos = db.Tripulantes
    .Where(t => t.Rango == "Piloto")
    .OrderByDescending(t => t.Puntos)
    .Select(t => new { t.Nombre, t.Puntos });

Console.WriteLine(pilotos.ToQueryString());   // muestra el SQL que se enviará:
// SELECT t.nombre, t.puntos FROM tripulantes AS t
// WHERE t.rango = 'Piloto' ORDER BY t.puntos DESC

// CRUD sin escribir SQL
db.Tripulantes.Add(new TripulanteEf { Nombre = "Alejo", Email = "a@x.net" });
await db.SaveChangesAsync();                  // INSERT

Scrum y Kanban

      
Son maneras de organizar el trabajo de un equipo. En una pasantía lo más probable es que entres a un equipo con Scrum y un tablero en Jira, Azure DevOps o GitHub Projects.

      

        
ScrumKanban

        
RitmoSprints fijos de 1 a 4 semanasFlujo continuo

        
RolesProduct Owner, Scrum Master, equipoNo obligatorios

        
ReunionesPlanning, Daily de 15 min, Review, RetrospectivaLas que el equipo necesite

        
Regla claveEl objetivo del sprint no cambia a mitadLímite de trabajo en curso (WIP)

        
Ideal paraProducto nuevo con entregas frecuentesSoporte, mantenimiento, tickets

      

      
En la Daily cada persona responde tres cosas: qué hizo ayer, qué hará hoy y qué la está bloqueando.
